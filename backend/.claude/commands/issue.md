"$ARGUMENTS" 작업에 대한 GitHub 이슈를 이음 백엔드 이슈 템플릿 형식으로 작성하세요.

## 작성 절차
1. 작업 설명에서 작업 유형을 판별한다 (복수 선택 가능)
2. 관련 도메인 코드를 가볍게 확인해 작업 내용을 구체화한다 (파일 전체를 읽지 않는다)
3. 완료 조건은 검증 가능한 형태로 작성한다 — "잘 동작한다"(나쁨) vs "동일 paymentId 2회 호출 시 1회만 처리된다"(좋음)

## 작성 규칙
- 제목: `[BE] {작업 요약}` — 간결한 명사형 (예: `[BE] 채팅방 멱등성 처리 구현`)
- 작업 내용: 구현 단위로 쪼개서 작성 — 각 항목이 커밋 1~2개 분량이 되도록
- 완료 조건: 테스트로 검증 가능한 기준 우선. 동시성/멱등성 관련 작업이면 STP 시나리오 ID(IT-ORD-003 등) 연결
- 참고 사항: 이음 코딩 표준 중 이 작업에 특히 해당하는 규칙을 1~2개 명시
  (예: 분산 락 필수, Soft Delete 대상 아님, 도메인 이벤트 경유 등)
- 브랜치명 제안을 마지막에 추가: `feature/{기능명}`

## 출력 형식 (아래 템플릿 그대로 사용)

```markdown
[BE] {작업 요약}

## 📄 작업 유형
- [ ] 기능 개발
- [ ] 화면 개발
- [ ] API 개발
- [ ] 문서 수정
- [ ] 버그 수정
- [ ] 리팩토링
- [ ] 테스트

## 🎯 작업 목적
{이 작업을 수행하는 이유}

## 📌 작업 내용
- {구현 단위 1}
- {구현 단위 2}
- {구현 단위 3}

## ✅ 완료 조건
- [ ] {검증 가능한 기준 1}
- [ ] {검증 가능한 기준 2}
- [ ] {검증 가능한 기준 3}

## 🔗 관련 문서 / API
- {SDD 섹션, API 명세, 관련 Controller 경로 등}

## 📎 참고 사항
- {적용해야 할 이음 코딩 표준, 주의점}
```

마지막에 제안 브랜치명을 별도로 출력: `브랜치: feature/{기능명}`
해당하는 작업 유형 체크박스는 `[x]`로 표시한다.
